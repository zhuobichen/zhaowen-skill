# 真正搞懂：两个方向

> 溯源：Karpathy「我们将花越来越多的时间去理解语言模型的输出」＋ ASD-STE100（1980 年代航空维修手册的受控自然语言）＋ 公众号《如何用 Codex 以 10 倍速度学习任何东西》。
>
> 内核：**两个方向打的是同一个东西——「看着懂了」的错觉。**
> - **方向 A（读）** AI 输出 → 你读懂。靠**换输出形态**降低理解成本。
> - **方向 B（讲）** 你输出 → AI 评判。靠**逼你输出**暴露漏洞。
>
> 原文那句最直白：「把方向反过来：不是 AI 输出你接收，而是你输出，AI 评判。」

---

## 第 0 步：先判方向

| 用户的情况 | 方向 |
|---|---|
| 面前有一堆看不懂/看不下去的东西 | **A（读）** |
| 想学一个新东西、想被人考、想检验自己会不会 | **B（讲）** |
| 两个都有 | 先 A 快速建立地图，再 B 逼自己输出 |

判错的代价：该读的时候去考，是浪费时间；该讲的时候只读，就是又一次「看着懂了」。

# 方向 A（读）：AI 输出 → 你读懂

## A0 先定读者的动作，再选形态

不要一上来选形态。先答三句（答不出就问用户，别猜）：

1. **谁看？** 自己 / 同事 / 外行 / 三个月后的自己
2. **看完要做什么？** 决策 / 复现 / 上手操作 / 只是心里有数
3. **在哪看？** 终端 / 浏览器 / 手机 / 会上投屏

| 读者要做什么 | 选哪级 | 产物 |
|---|---|---|
| 弄清一段话到底在说什么 | **A1** | 受控语言重写 |
| 记住结构 / 关系 / 因果 | **A2** | 一张图 |
| 上手试、调参数、看变化 | **A3** | 单文件 HTML |
| 理解一个**过程**（推导、变化、算法怎么跑） | **A4** | Manim 视频 |

**一次只上一级。** 四级全做是炫技。先 A1，不够再加——大多数时候 A1 就够了。

## A1 受控语言重写（ASD-STE100）

**为什么有效**：STE100 是给空客/波音维修手册设计的受控自然语言。它假定读者是**非母语技术人员、读错会出人命**，于是把歧义规则化了。大模型对这种规范极熟——直接要就行。

**硬规则（这些是 STE100 的，不是我的发明）**：

- 程序句 ≤ **20** 词；描述句 ≤ **25** 词
- **一句一个指令**，不要「并且/然后」串烧
- 主动语态、现在时
- 只用批准词表里的词，**一个词只有一个意思、一个词性**
  （`test` 只准当名词；`close` 只准当动词，"靠近"必须写 `near`）
- 不用同义词换着说——同一个东西，全文用同一个词
- 不用完成时、不用 -ing 当动词、不用被动
- 名词串 ≤ 3 词（`engine oil pressure sensor` 就该断）
- 一段一个主题，段 ≤ 6 句

**中文场景的移植**（中文没有批准词表，按规则精神来）：

- 词数换成**字数**：一句 ≤ 20 字（程序）/ ≤ 25 字（描述）
- 禁用中文特有的稀释结构：`进行 / 实施 / 予以 / 加以 / 有效地 / 一定程度上 / 值得注意的是 / 综上所述`
- 动词不要名词化：`进行检测` → `检测`，`做出判断` → `判断`
- 同一概念全文同一词：不要「模型 / 大模型 / LLM」混着说

**必须跑的验证**（不跑就只是在写散文）：

```bash
python scripts/ste_lint.py <改写后的文件>
```

它报出：超长句、被动/完成时/-ing 候选、稀释词。**报告里只有 candidate，没有 verdict**——完整批准词表是 ASD 的版权物，任何脚本都做不到 100% 合规判定。

所以对用户的说法是：「**按 STE100 规则收紧过，超长句 N 处已修**」，**不要说**「符合 STE100」。

> 降级用法：嫌太严就要求「达到 ASD-STE100 的 80% 程度」（Karpathy 原话）。但降级的是措辞严格度，**不是**跑 lint 这一步。

## A2 一张图

选型按**关系形态**，不按好看：

| 内容 | 用什么 |
|---|---|
| 因果 / 流程 / 状态机 | mermaid `flowchart`（能进 md、能进 GitHub 渲染） |
| 架构 / 层次 | mermaid `graph` 或手写 SVG |
| 数量对比 / 趋势 | matplotlib（脚本可复现，别手画） |
| 抽象概念对照 | 手写 SVG，左右两栏 |

**硬约束**：图上每个字都必须是**读者需要的**；节点 ≤ 7±2，超了就拆两张；方向统一（左→右 或 上→下）。

**必须回看**：渲染成 PNG，然后用 Read 工具**自己看一眼**。代码跑通 ≠ 图是对的。文字重叠、标签被裁掉、箭头指错方向，全都不报错。

## A3 单文件可交互 HTML

用在「读者要动手试」的时候。

- **单文件**：HTML + CSS + JS 全在一个文件里，双击就能开
- 外部依赖要么内联，要么明确允许 CDN 并在页面上写「需联网」
- `<meta charset="utf-8">`；中文字体给 fallback
- 有交互就在最上面放一句「怎么玩」

**先设计成「JS 坏了也不影响读」**（渐进增强）：

- **正文写在 HTML 标记里，JS 只加行为**（切换、筛选）。这样即使脚本报错，读者看到的仍是完整内容，不是空白页。
- 脚本末尾留记号：`document.documentElement.setAttribute('data-js','ok')`，异常分支写 `'err'`。这样"JS 到底跑没跑"有外部证据，不靠猜。
- 页面从 `file://` 打开时，`fetch` 和 ES module 导入常被浏览器拦。别依赖它们。

**必须验证**（这级翻车最多）。首选 `bsk`：

```bash
bsk session start                              # 记下 4 位 session id
bsk navigate "file:///D:/path/demo.html" --session <id>
bsk get-html --session <id>                    # 数关键节点在不在
bsk screenshot --session <id>                  # 把图 Read 出来看版式
bsk session stop <id>
```

**`bsk` 没装时的等效退路**（Edge/Chrome 无头，Windows 上 Edge 一定有）：

```bash
EDGE="/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
"$EDGE" --headless=new --disable-gpu --hide-scrollbars --dump-dom \
  "file:///D:/path/demo.html" > dom.html        # 数节点 + 查 data-js 记号
"$EDGE" --headless=new --disable-gpu --hide-scrollbars \
  --screenshot="D:\out.png" --window-size=1180,6400 "file:///D:/path/demo.html"
```

三条容易漏的：

- **不能只截图说「看着没问题」。** 先数清预期节点数（`grep -c`），再截图看版式——截图证明不了「没渲染的东西本来就没有」。
- **截图会静默截断长页面**：`--window-size` 高度不够时画面在底部被切开，看起来却像正常结尾。用像素扫描量出内容真实高度，不够就加高重截。
- **数节点时别把断言写错**：`class="controls"`（容器，1 个）和 `<button>`（3 个）不是一回事。数值对不上时，先怀疑断言，再怀疑页面——但两种可能都要真的排除掉。

## A4 Manim 解释视频

Karpathy 最看好的一级。适合讲**过程**：推导、变化、算法一步步怎么跑。

**前置依赖（本机实测：全部缺失，先装再承诺）**：

| 需要 | 检查 | 装法 |
|---|---|---|
| Python manim | `python -c "import manim"` | `pip install manim` |
| **ffmpeg**（必须，manim 靠它编码） | `ffmpeg -version` | `winget install ffmpeg` |
| LaTeX（只有公式 `MathTex` 需要） | `xelatex -version` | 装 MiKTeX |
| TTS（旁白） | — | `pip install edge-tts`（免费）或 ElevenLabs API（要 key） |

**管线**：写场景脚本 → `manim -ql scene.py Scene`（`-ql` 低清快渲染，先确认再出高清）→ mp4 → TTS 出音频 → ffmpeg 合轨 → 验证。

**必须验证**：

```bash
ffprobe -v error -show_entries format=duration -show_entries stream=codec_type,width,height -of default=nw=1 out.mp4
ffmpeg -ss 3 -i out.mp4 -frames:v 1 frame.png    # 然后 Read 这张 frame.png
```

只看「manim 退出码 0」不算成功。常见翻车是全黑帧、或只有标题停留 3 秒。**时长和画面都得看。**

# 方向 B（讲）：你输出 → AI 评判

原文的六法，按顺序用。**每一步都标了它自己的失败模式**——这六法全都长着一副"已经生效了"的样子，而那正是问题。

## B1 先搭一套学习阶梯

别一上来冲复杂项目。基础概念还没连起来就去看高级教程，会出现「每个词都眼熟，自己动手又接不上」。

```
请把「XX」拆成 5 个学习等级，从完全新手到能独立做项目。
每一层告诉我：① 需要掌握什么 ② 常见错误是什么
③ 应该做什么练习 ④ 达到什么标准才能进入下一层
```

这一步是先拿地图。你会知道自己在哪一层、下一步补什么、什么时候算真的过关。

> **失败模式**：阶梯是通用模板，跟你的实际目标没关系——看着像地图，其实是网上下载的。
> **检查**：第一层能不能**今天就做完**？做不完就是拆得不够细。

## B2 找出最值得先学的 20%

任何技能里都有一部分内容最先带来回报。学剪辑不用一开始研究所有插件，学编程也不用一上来啃完整文档。

```
我想用 20 小时学习「XX」。
请找出这个主题里最重要的 20% 内容，并设计成 10 次学习计划，每次 2 小时。
每次都要包含：学习目标、练习任务、复盘问题。
```

学习最怕「大而虚」。一旦变成 10 次明确的训练，执行难度会低很多。

> **失败模式**：「最重要的 20%」是编出来的，读着很专业但无从验证。
> **检查**：每次 2 小时结束时，你能不能**独立产出一个东西**（一段代码、一页笔记、一个能跑的例子）？不能就是这次计划是空的。

## B3 让 AI 当考官，**一次只问一个问题**

很多时候我们以为自己学会了，其实只是看懂了别人怎么讲。真正检验理解，要靠自己说出来、做出来、答出来。

```
我刚学完「XX」，请你当我的考官。
一次只问我一个问题，从简单到困难。
我回答后，请给我打分，并指出：哪里对，哪里错，哪里理解不完整。
然后只重新解释我没掌握的部分。
```

**最关键的是「一次只问一个问题」。** 别让 AI 一口气出 20 道题——一问一答，反馈才具体，你的薄弱点会立刻露出来。

> **失败模式**：模型的天性就是一口气列 20 道题。你不数，它就会这么干，而这一整法的价值全在"一次一问"上。
> **检查**：**数它一次问了几问**。大于 1 就是没生效，让它重来。

## B4 每学完一块，做一页速查表

不要把整段聊天记录存下来——太长了，后面基本不会再翻。

```
请把我刚刚学的内容整理成一页速查表。包含：
① 一句话定义 ② 核心概念 ③ 真实例子
④ 常见错误 ⑤ 使用前检查清单 ⑥ 5 个自测问题
```

适合考试前、面试前、组会前、开题前看。不用重学一遍，只要把脑子里的结构唤醒。

> **失败模式**：速查表变成又一份长文——那就没省下任何东西。
> **检查**：**一页装得下吗**？装不下就砍。做这页时可顺手用方向 A（A1 收紧文字 / A2 画成图）。

## B5 让 AI 帮你筛资源

现在学习最麻烦的地方往往是资源太多：书、课程、视频、博客、社群收藏了一堆，最后哪个都没开始。

```
我想学习「XX」。请帮我筛选最值得看的 5 个资源。
每个资源说明：适合谁、难度如何、该怎么用、哪些部分可以跳过。
最后用这 5 个资源，帮我设计一个 7 天学习路径。
```

这一步是在减少选择成本。真正有用的学习路径不需要堆满资料——能看完、能练、能复盘，才有价值。

> **失败模式**：**推荐出一堆不存在或早已过时的资源。** 这是六法里幻觉风险最高的一步，因为没有东西会报错。
> **检查**：逐个确认资源**真实存在**（链接能打开、书名对得上作者）。打不开的当场划掉，别让它进路径。

## B6 费曼法：逼你讲明白

如果一个概念你讲不清，大概率还没真正理解。

```
请先用 12 岁孩子能听懂的话解释「XX」。
然后我会用自己的话复述。
你帮我判断哪里讲对了，哪里漏了，哪里混淆了，
哪里用了听起来高级但其实没说明白的词。
然后让我重新讲一遍，直到我讲清楚为止。
```

特别适合抽象概念。很多知识看答案时很清楚，等自己开口讲，漏洞才会冒出来。

> **失败模式**：**AI 说你讲得很好，就通过了。** 模型倾向于夸人，这一法会在"一片赞美"里静默失效。
> **检查**：逼它**至少指出一处**漏洞、模糊点或"听起来高级但没说明白"的词。一处都说不出，就换个更狠的提示词重来。

## B7 把六步连起来

```
① 先搭学习阶梯      → 知道自己在地图的哪里
② 找出最重要的 20%  → 砍掉大而虚
③ 按 10 次计划执行  → 每次都有产出
④ 每学完一块，让 AI 考你 → 暴露薄弱点
⑤ 通过后整理一页速查表 → 把结构固化下来
⑥ 对讲不清的地方，用费曼法反复讲 → 直到真的懂
```

AI 辅助学习最实用的地方就在这里：**帮你设计路径、压缩重点、制造反馈、逼你输出。**

# 贯穿两个方向：验证优先于生成

两个方向共用一个失败模式：**看起来成了，其实没有，而且不报错。**

| 环节 | 静默失败长什么样 | 怎么抓 |
|---|---|---|
| A1 | 读起来通顺，但超长句一堆 | 跑 `ste_lint.py` |
| A2 | 图渲染成功，文字重叠/被裁 | Read 渲染出的 PNG |
| A3 | 页面打开了，JS 报错后半个页面没了 | 数节点 + 截图 |
| A4 | mp4 有了，但是全黑/3 秒 | `ffprobe` + 抽帧 Read |
| B3 | AI 一口气出 20 道题 | 数它一次问几问 |
| B4 | 速查表变成又一份长文 | 看一页装不装得下 |
| B5 | 推荐了不存在的资源 | 逐个打开链接 |
| B6 | AI 夸你"讲得很好"就过关 | 逼它指出至少一处漏洞 |

**规矩：每一步都要有一个「用眼睛、用数字、或逼对方给负面反馈」的确认动作。**
不能以「命令返回成功」结案，**也不能以「AI 说你做对了」结案**——后者是方向 B 独有的坑。

---

## 什么时候不要用

- 用户只是要摘要 → 别上 A2/A3/A4，A1 甚至纯摘要就够
- 用户要的是**调研**或**写作** → 那是 hv-analysis / khazix-writer 的活，别抢
- 内容本身没结构（一堆平铺的事实）→ 画图只是把废话画成图
- 读者不会打开浏览器 → A3 白做
- 用户只想**要个答案**、不想学 → 方向 B 是折磨，别硬上
- 你没空验证 → **宁可降一级，也别交付没看过的图/页面/视频**

- `scripts/ste_lint.py` — A1 的句长/句式候选检查器（启发式，不给合规结论）
- `references/ste100-rules.md` — STE100 规则详解 + 中文移植对照表
- `references/learn-with-ai.md` — 方向 B 六法的原文要点与可直接复制的提示词
