# 海克斯大乱斗分析助手

配套 MCP：`aram-mayhem`（44 个工具，只读为主，唯一写操作是选人频道发消息）。

**别背工具名。** 第一句先判「用户处在哪个处境」，再落到工具；拿不准就调
`mcp__aram-mayhem__get_help`——它按处境给引导，和 MCP README 那张表同源（那张表是生成的，
不会过期）。本 skill 不重复那张表，只补它给不了的东西：**怎么问才问得对、结论能信到哪、故障了怎么归因**。

## 一、开口前先做两件事

1. **确认身份与数据来源**：`mcp__aram-mayhem__get_my_account_status`
   ——需要**客户端正在运行且已进大厅**（登录/更新界面时本地接口还没起来）。
2. **读输出里的「数据来源 + 截止时间」**：客户端在线时是「客户端 ∪ 归档 ∪ SGP 全量」，
   离线时退回归档并标「截止到什么时候」。**同一个问题的答案会随数据源变化**，
   转述时必须带上这个时间戳，否则用户会拿旧数去对客户端的新数。

需要更长的历史就先问一句要不要 `refresh_data` 之外的 `archive:sync`（见第五节）。

## 二、数一个确定的事实（最常见，也最容易数错）

用户问「X 号打了几把」「昨天几把」这类**要一个精确数**的问题：

- **用 `get_game_detail` 传 `which: "2026-10-11"`**。它会把那天命中的对局**逐条列出来并给总数**，
  再让你指定其中一把看详情。这是唯一能同时给「数」和「清单」的问法。
- **不要**用 `get_my_recent_games` 传个 limit 自己数——那是滑动窗口，
  窗口边界正好压在你要的那天时，你会**少算而不自知**。
- 同理：`limit` 是「最多看几把」，不是分页；它不会因为你调大就回溯到更早。
- 数完顺手给**胜负拆分和时段分布**（哪几段、最长连胜/连败），这才是用户真正想看的，
  单纯一个数字他多半自己也会数。

## 三、判读规矩：这些输出是相关性，不是因果

这个 MCP 做了大量「你 × 胜率」的切分，**全部是观察数据**。转述时按这几条收着说：

| 工具 | 容易说错的地方 |
|---|---|
| `get_my_builds` / `get_counter_items` | 「出它胜率高」≠「出它就能赢」。赢的队结束得快，反而更容易剩散件——所以只统计成装 |
| `get_enemy_comps` | 「对面有坦克时胜率高」是同向变化，不是坦克让你赢 |
| `get_my_contribution` | 会专门给「全队都顺」的对照，用来区分「你 carry」和「赢得顺所以数据好看」 |
| `get_my_tilt` | 胜率本来就会向 50% 回归；接近基准就是**没影响**，别讲成「心态稳」 |
| `get_empirical_augments` / `get_augment_pairs` / `check_synergy_sets` | 符文是玩家**自选**的，强符文会被会玩的人拿走 → 含选择偏差；且样本只是本机几个账号排到过的人，不代表全服 |
| `get_tft_detail` | 云顶是「**最终阵容**」口径（收场时带着它），不是「拿了就能赢」 |

**样本门槛必须遵守**：补丁对比要单补丁 ≥15 局、趋势要每周 ≥5 局、队列 <10 局只报数字、
体检里样本不够的维度会单独列出。工具自己会拒绝下结论时，**照着它的措辞走，别替它补一句更硬的**。

## 四、数据源与窗口：为什么答案会变

三层，理解的顺序是「谁更全」：

| 层 | 覆盖 | 特点 |
|---|---|---|
| 本地客户端 LCU | 海斗最近 **200 局**、云顶 **20 局** | 翻页参数会被忽略（给 500 也是 20）；给**细节**（`playerAugment1..6` 符文） |
| 腾讯 SGP 后端 | 真分页，实测上千局（海斗 311 / 云顶 684） | 给**广度**；`gameVersion` 只有它给 |
| 本地归档 `data/archive/` | **只增不减**，离线可用 | 攒久了覆盖面超过接口窗口；分析默认用「归档 ∪ 本回合」的全量 |

→ 所以「我的总局数」会**随时间变大**。出现「这个说 306 把、那个说 304 把」时，
先查是不是一次查询刚并入了新对局，而不是怀疑有 bug（MCP 自带 `audit:consistency` 在盯这件事）。

**云顶与海斗走的是两个归档文件、两套字段**（`placement` vs `win`），不要混着算。

## 五、上游挂了怎么办 —— 别把服务器的锅算到接口头上

**这条单独立了一份，遇到「读不到数据 / 返回空」先看它：**
[`references/data-source-failures.md`](references/data-source-failures.md)

一句话版：**5xx/超时/拒连是上游，字段缺失/解析失败才是自家**；同一条路径上多个对象一起挂、
或官方客户端自己也在报「无法连接」，就不要再改代码了。恢复后**要回填**（`archive:sync`），
否则窗口期的对局会永久缺失。

## 六、要输出物时，四种形态各管一头

| 要什么 | 用哪个 |
|---|---|
| 求全、能反复看、能留档 | **单人 HTML 报告没有 MCP 工具**，只能命令行：在 MCP 目录跑 `npm run report:html`（海斗 14 图 + 一节「深入分析」；云顶用 `npm run report:tft`）。要给别人出报告加 `--friend 名字` |
| 一屏看完、能直接贴出去 | MCP：`export_report_markdown` |
| 要和别人并排比 | MCP：`export_compare_report`（双账号 HTML） |
| 要自己算 | MCP：`export_games_csv`（39 列，带 BOM，Excel 直开不乱码） |
| 现在 vs 从前 | MCP：`export_self_compare_report`（按局数对称切；窗口和 `get_my_trend` 不同，两者不一致时**不替你调和**） |

报告产物落在 MCP 目录的 `reports/`（含账号名，已 gitignore）。铁律里那条
「图型要多样、正文以分析为主、明细折叠」在这里同样适用。

## 七、红线

- **只有一个写操作**：`send_champ_select_message`（选人频道发一条**你给的原文**，需 `confirm: true`）。
  不要自动生成评价发出去。
- **对局内的我方/所有人频道做不到，也不做**（不走 LCU，实现要注入游戏进程，会撞腾讯条款与 ACE）。
- 好友相关只能查**好友列表里的人**，且只能读到**本机客户端缓存的那部分**，不是对方生涯总场次。

## 八、已知坑（踩过的）

- `get_my_contribution` 传 `who`（查好友）时，**标题写的仍是调用者的名字**——别据此判断数据串号。
- `get_my_recent_games` 返回的「共取到 N 把」跟归档总数**不是一个数**：前者是窗口，后者是全量。
- 拿不到「对局内实时三选一推荐」——那是游戏进程直接下发的，本地接口与官方 Live Client Data 都没有。
  已打完的对局能读到符文，过程中的不行。
- 外号/昵称靠 `data/aliases.json` 手工维护，缺的可以补；查不到英雄时先试英文 id 或官方称号。
- 本地文件行尾是 **CRLF**，正则里别用 `\n` 硬匹配。
