# 数据源故障归因：先分清是「我们的接口」还是「上游服务器」

> **教训**：2026-10-11～12 想数 11 号的对局，`get_my_recent_games` / `get_game_detail` 全线读不到东西。
> 一路查下去才发现**不是 MCP 的问题、也不是账号的问题，是上游对局服务整段挂了**。
> 2026-10-13 它自己恢复，一次查询就补回 207 局。
>
> 这类事的代价不对称：**误判成自家 bug** → 白改代码、甚至"修"出真 bug；
> **误判成上游** → 结论停在原来。所以判据要往"先证明是上游"的方向要证据。

## 一、判据（按顺序问，能停就停）

1. **同一条路径上，别的对象也挂吗？**
   换几个 puuid / 几个大区 / 几个好友，打同一批接口。
   实测：HN1 上 **6 个好友全部 500/503** → 排除「这个账号的数据有问题」。
2. **官方客户端自己怎么说？**
   打开英雄联盟客户端看战绩页。实测它弹「**无法连接到比赛记录服务**」
   → 上游自己承认挂了，别再往下查代码。
3. **服务到底还活着吗？**
   用一个**明显不存在**的 puuid 打同一台主机。
   实测：返回 `200 {"games":[]}` → **服务是活的、路由是通的**，
   说明不是"我们连不上"，而是"这台主机上这批真实数据取不到"。
4. **错误的性质是哪一类？**

   | 症状 | 更可能是 |
   |---|---|
   | 5xx / 超时 / 连接被拒 | **上游** |
   | 200 但 `games: []`（对象不存在时也这样） | 上游数据侧，或该对象本就无记录 |
   | 4xx 参数/鉴权错 | 自家（参数、token、大区） |
   | 返回了但字段缺失 / 解析失败 | **自家**（口径或数据结构变了） |

5. **时间相关性**：几分钟前还正常、现在全挂 → 抖动，不是回归。
   反之，某次改动之后**持续**不对 → 才该怀疑自己。

## 二、别做的事

- **别把「读到 0 局」渲染成正常结果。** 工具的头部会标来源与截止时间，
  读它；如果上游是 5xx，正确的话是「上游服务异常，不是你没打」。
  一个"0 把"和一句"服务挂了"对用户是完全不同的信息。
- **别急着加重试、换路径、改代码。** 先定范围——范围没定就动手，等于在赌。
- **别把上游 5xx 写进「本服务的已知限制」。** 那是**当时的**服务器状态，不是服务的性质；
  写进文档会腐蚀这份文档的可信度（下次真出 bug 时没人信）。

## 三、恢复之后：必须回填

上游挂掉的窗口期，如果只是"等下次查询顺带补"，**边界上的对局可能永远进不来**
（客户端只给滑动窗口，你补的时候它可能已经滑出去了）。

```sh
npm run archive:sync              # 把当前账号的对局并进归档
npm run archive:sync -- --friends # 连好友一起
```

实测 2026-10-13 恢复后：归档 **318 → 525** 局（一次并入 207 局），时间跨度补到 2026/10/12。
**"接口恢复了" ≠ "数据回来了"**，这两步要分开确认。

## 四、上游长期不可用时的备选路径

MCP README 里各自有完整步骤与风险，这里只给选型：

| 路径 | 代价 | 注意 |
|---|---|---|
| 腾讯 SGP（默认已在用） | 低 | 仍需客户端在线并登录 |
| 本地归档 | 零 | 只增不减，离线可分析；但补不回已错过的历史 |
| **WeGame 战绩** | 中 | 要登录态，cookie 会过期；`lib/wegame.ts` 里已有实现，但**未接成工具** |
| 掌盟抓包 | 高 | 要 mitmproxy + 手机装证书；**复用掌盟登录态比本地 LCU 只读的暴露面更大**，是否值得由用户判断 |

选之前先问一句：这条数据**现在**就要，还是等得起？多数情况下等上游恢复 + 回填是最省事、最安全的。

## 五、判据自己也会骗人

「读到 0 条」至少有四种来源，别只想到一种：
① 上游真挂了；② 对象/大区/时间条件记错；③ 分母被换（查的不是同一个账号）；
④ **代码压根没跑到**（改了没生效 / 早退 / 缓存）。

以及一个指纹：**结果恰好是某个整齐的整数倍**（比如正好 2 倍、正好 200 的整数倍）
——先怀疑重复计数，而不是"数据真多"。
