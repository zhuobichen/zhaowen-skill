# 公众号模板库

把「看到一个好排版」变成「能吃进来的可复用主题」。

## 核心工具：`scripts/extract_theme.py`

```bash
# 从已发表文章 URL（用 browser-act 免登录打开，公开文章不用扫码）
python scripts/extract_theme.py --url "https://mp.weixin.qq.com/s/xxx" --name redcard2026

# 从本地 HTML（整页或只给正文片段都行）
python scripts/extract_theme.py --html ./body.html --name xxx --preview ./shot.png
```

产出 `templates/<name>/`：

| 文件 | 内容 |
|---|---|
| `theme.json` | 设计令牌（配色/字体/字号/行高/圆角/阴影/间距）+ 组件形态，机器可读 |
| `reference.md` | 人读的反推记录 + **人工复核清单** |
| `sample.html` | 抠下来的正文 HTML，对照用 |
| `preview.png` | 渲染截图 —— **最重要的对照物** |

## ⚠️ 这个 skill 存在的理由：数值对 ≠ 模板对

2026-09-30 实测踩到的坑：反推一个红色卡片模板，**颜色、圆角、字号、阴影全部解析正确**，
但结构错三处 ——

| 解析出来的 | 实际 | 
|---|---|
| 章节标题条 = 左标签 + 右胶囊（两端布局） | **红方块 + 英文小字 + 中文标题**（三件套） |
| 引用块 = 圆角浅底 | 还多一根 **`border-left` 红竖线** |
| 胶囊 = 纯文字 | 内嵌一个 **6px 小红圆点** |

**三条都不是「数值差一点」，是「少了个元素」。数值可以推理，缺元素只能看。**

所以：**`theme.json` 永远不足以还原模板，必须打开 `preview.png` 人眼对照。**
`reference.md` 里那份「人工复核清单」就是为此存在的，别跳。

### 两个已修的识别 bug（同类错误的模板）

1. **只在 `<section>` 里找组件** → 胶囊、圆形序号常挂在 `<span>` 上，会**整类漏掉**。
   已改为 `where='both'`。
2. **用「线宽 ≥2px」区分标题条和行内高亮** → 实测里标题条 3px、高亮 2px，
   但两者本来就不该靠粗细分。**靠挂载位置**（section vs span）才是稳的判据。

> 教训：判据要选**语义上必然不同**的那个维度。粗细、颜色这类连续量容易重叠；
> 挂载位置、标签类型这类离散量不会。

## 已修的三个缺陷（都是实测撞出来的）

### 1. 只在 `<section>` 里找组件 → 整类漏
胶囊、圆形序号常挂在 `<span>` 上。已改为 `where='both'`。

### 2. 用「线宽 ≥2px」区分标题条和行内高亮 → 判据选错
实测标题条 3px、行内高亮 2px，但**两者本来就不该靠粗细分**。
改用**挂载位置**（section 上是标题条、span 上是高亮）。

> 教训：判据要选**语义上必然不同**的维度。粗细、颜色这类**连续量**容易重叠；
> 挂载位置、标签类型这类**离散量**不会。

### 3. 组件签名只覆盖「见过的模板」→ 新模板整类漏 ⭐ 最重要
签名（卡片/标题条/分隔线…）都是从第一个模板总结的。反推第二个（灰调极简）时，
它是双圆点列表 + 1px 描边盒 + 深色块，**签名一个都不匹配**，只认出 3 项。

修法不是「再多猜几个签名」—— 而是 output 里增加一节 **`structure`（结构事实）**：
标签普查、所有 border / background / display declaration、小尺寸元素。
这些是**事实**，不会因为我没猜到就漏。

> 教训：**用「事实枚举」兜底「模式识别」**。模式识别必然有覆盖边界，
> 而边界外的东西不会报错、只会静默消失。加一层不依赖任何假设的原始事实，就兜住了。

### 4. 以为「标题条 = 下划线式」→ 漏掉底色式
第一个模板的章节头是 `border-bottom: 3px solid`（下划线式），我就只按这个写签名。
第二个模板的章节头是 `background:#222222; color:#FFF; text-align:center`（**底色式**），
一点 border 都没有 —— 整类漏掉。这条是**人工复核**时抓到、不是脚本自己发现的。

已补 `filled_label` 签名：实色底 + 内边距 + (大字号 or 居中)。

> 教训：**同一个语义位置可能有多种实现手法**。别把「第一个样本的做法」当成该类别的定义。
> 判断「这是不是标题条」应该看**它在这个位置起什么作用**（承接上下文的分段）而不是
> 「它有没有某个具体属性」。脚本做不到这层语义，所以人工复核那一步不能省。

### 5. 分隔线只认「渐变 + 1px」→ 漏掉纯色 2px
第三篇用的是 `background-color: rgba(163,236,66,0.19); height: 2px` —— 纯色、2px、无渐变，
按当时的签名整类认不出（实测 49 处）。已补 `thin_bar`（高 ≤4px + 有底色）。

### 6. 差点把 60 个空 SVG 当成装饰件统计 ⭐
第三篇有 60 个 `<svg>`，看着像"用了 60 个 SVG 图标"。**实际全是微信编辑器的空占位符**：

```html
<svg viewBox="0 0 1 1" style="width:0" role="img" aria-label="插图"></svg>
```

`width:0`、无内容、60 个完全相同。**这条是"先看再改"救回来的** ——
当时正准备加 `svg` 检测器，先去看了原始 HTML，才发现加它是错的。

已改为 `svg_real`：先滤掉 `width:0` 的，第四篇验证有效（40 个 → 滤掉 27 → **13 个真的**，
与 `<g>` 标签数 13 吻合；截图里那个圆形纹章就是其中之一）。

> 教训：**加检测器之前先看它到底长什么样**。统计一个标签类型的出现次数很容易，
> 但「这个标签在这里是什么」是另一回事。不先看一眼，就会把一个纯噪声项
> 当成有意义的指标写进产物 —— 而且它**看起来特别像真的**。

### 7. `<mp*>` 不能笼统数 —— 一类标签里混着真组件和空标记
第五篇（新闻体）有 3 个 `<mp*>`。笼统数会得出「3 个嵌入组件」，**错的**。
逐个看实际标签名才分得清：

| 实际标签 | 是什么 | 该不该计数 |
|---|---|---|
| `<mp-common-videosnap>` | 视频号视频卡片 | ✅ 该 |
| `<mp-common-profile>` | 公众号名片 | ✅ 该 |
| `<mp-style-type>` | 样式标记（`data-value="3"`，无内容） | ❌ 不该 |

已改为**按具体标签名分别识别**（`mp_video` / `mp_profile` / `mp_audio` /
`mp_miniprogram` / `mp_article`），剩下归到 `mp_other` 并注明「多为无意义标记」。

> 教训：**前缀相同的标签不一定是同一类东西。** 数一个前缀之前，先看看这个前缀下
> 到底有几种标签、各是什么。这条和 #6 是同一类错误 —— 都是「数得太粗」。

### 8. 新检测器和旧检测器覆盖重叠 → 同一批元素被数两遍
加 `thin_bar`（高≤4px + 有底色）之后，红色模板报出 `divider 13` **和** `thin_bar 13` ——
**两个数字完全相等，因为就是同一批元素**：它的分隔线是渐变式，而 `thin_bar` 不排除渐变，
所以两边都算了。

这条是**回归检查**抓到的（改完检测器后重跑旧模板、逐项对比计数）。
不跑这一步不会发现 —— 两个数各自看着都合理，只有并排看才会注意到它们相等。

已修：`thin_bar` 排除 `gradient(`，渐变式归 `divider`。

> 教训：**改检测器后必须重跑旧样本并逐项 diff。** 新增检测器最容易造成
> 「两个名字数同一批元素」，而这类错误在任何单个结果里都看不出来 ——
> 只有比对才现形。修完后 `divider 13 / thin_bar 无` 才正确。

### 9. 同一个号反复用同一个模板 → 会收到重复项
收第六篇时发现它和 `graylist2026` **字体、配色、字号完全一致** ——
是同一个号（道哥说AI）的同一套样式，只是这篇更长、多露出 4 类组件。
再做一遍反推 + 人工复核是纯浪费。

已加**指纹查重**：`fingerprint()` 取「字体 + 有彩色主色」（滤掉透明、黑白灰），
`find_duplicate()` 与已有模板比对；命中则：

- `theme.json` 写入 `duplicate_of: <已有名字>`
- 控制台明确报出「同款模板已存在」+ 依据 + 处置建议

**处置策略**：若新样本更长/组件更全，**用它替换旧样本**（本次就是这么做的：
`graylist2026` 从 8 类升到 12 类）；否则直接删掉本次产出。

> 教训：**"收到一个新 URL" ≠ "得到一个新模板"。** 公众号的版式是**按号固定**的，
> 不是按文章变的。所以收模板应该**按号取样**，而不是按链接 ——
> 同一个号收第二篇的边际价值，主要在于「样本更全」，不在于「又一个新样式」。

## 依赖

- **browser-act CLI**：`uv tool install browser-act-cli --python 3.12`
  装在 `~/.local/bin/browser-act.exe`。只用来打开公开文章抠 `#js_content`，**不需要登录**。
- `--html` 模式不依赖浏览器，纯离线解析。

## 已知边界

- **只反推样式，不搬运内容**。`sample.html` 是留作对照的，别整段复用 ——
  那是别人的文章。抄版式可以，抄文字不行。
- **图片不处理**。`sample.html` 里的图是原站的 CDN 链接（`mmbiz.qpic.cn`），
  换文章时必须替换。
- **`preview.png` 需要外部提供**（`--preview`）。脚本自己截图要起浏览器，
  目前没内建；用 browser-act 截一张传进来即可。
- 微信会剥 `<style>` 和 `class`，所以**所有样式必须内联** —— 这是
  `clz_docx_to_mp` 那条流水线的硬约束，本库的产物要喂给它，同样受约束。
