# 横纵分析法深度研究

> 方法论溯源：融合索绪尔历时-共时分析、社会科学纵向-横截面研究设计、商学院案例研究法与竞争战略分析。
> 核心原则：纵向追时间深度，横向追同期广度，最终交汇出判断。

你正在执行一次横纵分析法深度研究，最终产出一份**排版精美的PDF研究报告**。

## 第一步：环境准备

1. **PDF转换脚本**：`scripts/md_to_pdf.py`（基于WeasyPrint）
2. **安装依赖**：`pip install weasyprint markdown --break-system-packages`
3. **写作风格**：内置于本Skill，无需额外加载

## 第二步：明确研究对象

1. 研究对象：产品名/公司名/概念名/人名
2. 类型：产品、公司、概念、人物
3. 研究动机（可选）
4. 特别关注点（可选）

## 第三步：联网信息收集（必须）

### 并行搜索策略（子Agent 3路并行）

- **子Agent 1 — 纵向**：起源、创始人背景、发展历程、关键事件、版本迭代、融资、战略转向、危机
- **子Agent 2 — 横向**：竞品识别、各竞品特点和用户口碑、行业对比、市场份额
- **子Agent 3**（复杂对象）：创始人深度背景、行业环境、用户社区（GitHub/Reddit/Twitter/知乎）

### 联网工具使用

```
你需要联网获取信息。使用以下工具：
- WebSearch：搜索发现来源，获取摘要和关键词
- WebFetch：已知URL时定向提取内容
- 如果有 web-access skill（检查 ~/.claude/skills/web-access/SKILL.md），优先加载遵循其指引
- 搜索策略：先用WebSearch发现线索，找到URL后用WebFetch深入提取，多次搜索多关键词组合
- 一手来源优先：官方博客 > 权威媒体原创报道 > 转载
- 学术类必查arxiv：用 https://export.arxiv.org/api/query
```

### 信息来源优先级

| 信息类型 | 一手来源 |
|---------|---------|
| 产品更新/技术决策 | 官方博客、GitHub Release、创始人推文 |
| 融资/商业数据 | 公司公告、SEC/工商文件 |
| 用户口碑 | GitHub Issues、Reddit、Twitter、知乎 |
| 行业分析 | 权威媒体原创报道 |
| 学术/技术原理 | arXiv论文、Google Scholar |

### 信息充分性自检

- 纵向：能讲出完整故事？有没有明显断层？
- 横向：竞品列表完整？每个竞品信息够对比？
- 来源：关键事实有可靠来源支撑？

**信息不够就补搜，不要凑合。**

## 第四步：纵向分析（6000-15000字）

沿时间轴还原发展全貌：

**起源追溯**：诞生的背景、技术/理念/需求、创始团队、当时的行业环境

**诞生节点**：首次发布/成立时间，最初形态和定位

**演进历程**：重大版本更新、融资事件、团队变动、战略转型、技术架构变化、用户规模里程碑、重大合作或收购、公关危机

**决策逻辑**：每个关键节点还原决策原因，为什么选A而不是B

**阶段划分**：萌芽期、快速增长期、转型期等

## 第五步：横向分析（3000-10000字）

### 竞品场景判断

- **场景A（无直接竞品）**：分析为什么没有竞品，未来竞争者从哪冒出
- **场景B（1-2个竞品）**：逐一深入对比
- **场景C（3个以上）**：选取3-5个代表性竞品深入分析

### 对比维度

- 核心差异：技术路线、产品形态、目标用户、核心优势短板、定价
- 用户视角：真实口碑、社区评价、用户体验偏差
- 生态位：占据什么位置、填补什么空白
- 趋势判断：机会和风险

## 第六步：横纵交汇洞察（1500-3000字）

精华段，给出综合性新判断：

1. 历史如何塑造了当下的竞争位置
2. 竞品的纵向对比
3. 优势的历史根源
4. 劣势的历史根源
5. 未来推演：最可能/最危险/最乐观三个剧本

## 第七步：写作风格

### 借鉴的核心元素

- **节奏感**：句子时长时短，段落跳跃自然，一句话自成一段制造重量感
- **叙事驱动**：有故事弧线，不写成流水账
- **知识是顺手掏出来的**：不"下面科普一下"
- **敢下判断**：有观点有事实，用"我觉得"承认主观性
- **层层剥开**：现象→表面解释→更深追问→核心洞察
- **文化升维**：连接到更大文化/哲学/历史参照
- **回环呼应**：前面埋的钩子后面callback

### 绝对禁区

- 套话："首先...其次...最后"、"综上所述"、"值得注意的是"、"不难发现"
- 空洞形容词："赋能"、"抓手"、"打造闭环"
- 教科书开头："在当今AI快速发展的时代"、"随着技术的不断进步"
- 高频踩雷词："说白了"、"意味着什么？"、"这意味着"、"本质上"、"换句话说"、"不可否认"
- 空泛工具名：不说"AI工具"、"某个模型"，要说具体名字
- 编造：搜不到的信息诚实标注「暂缺」，绝不编造

## 避坑清单（Gotchas）

1. **信息不够就停** - 宁多搜不凑合，信息密度决定报告质量
2. **一手来源 > 二手来源** - 多个媒体引用同一错误会造成循环印证
3. **竞品场景判断要准确** - 选错场景会导致分析方向偏离
4. **叙事不是年表** - "2023年1月发布A，2023年3月发布B"是流水账
5. **观点必须有事实支撑** - 推测要明确标注，不能当事实写
6. **用户口碑要真实** - 不要只有官方宣传，要有人真实声音
7. **升番逻辑** - 展示多个产品时，最弱的放前面，最炸的留最后
8. **扣主线句** - 偏离主线的段落后面要有扣主线句拉回来
9. **PDF依赖weasyprint** - 如果脚本运行失败，检查是否安装了依赖
