# 实体副屏：把第二块显示器做成“只读显示”

目标：一块只负责显示、不参与操作的副屏。用于盯远端桌面（ToDesk / 向日葵）或常驻状态面板，
**鼠标永远进不去**，人的注意力只落在主屏。

## 拓扑

```
主屏（独显输出）
   └─ 远端会话窗口（ToDesk 等）保持“非最小化”，藏在其他窗口后面
        └─ PrintWindow 抓帧 → HTTP /remote（1 秒）
             └─ 副屏：浏览器应用窗口铺满，指向 /remote
鼠标：CursorKeeper 限制在主屏矩形内
```

## 为什么不用远端软件自己的窗口直接放副屏

多数远端软件用**硬件叠加层（overlay）**渲染画面。叠加层在非主输出上常常无法使能，
表现为：窗口有内容、`PrintWindow` 抓得到，但**屏幕上全黑**。
换分辨率、最大化、铺满都无法解决；关掉它的“硬件加速/硬解码”也不一定生效。

所以走 `PrintWindow` + 浏览器显示这条路：渲染由浏览器负责，远端软件的叠加层问题被绕开。

## 关键实现点

### 1. 抓图必须用 `PrintWindow`，且窗口不能最小化

```python
user32.PrintWindow(hwnd, hdc, 0x00000002)   # PW_RENDERFULLCONTENT
```

- 对**被遮挡**的窗口有效（不需要它在最前）
- 对**最小化**的窗口只返回黑图 —— 所以守护脚本要防止/撤销最小化

### 2. 窗口定位必须 DPI 感知

```python
ctypes.windll.shcore.SetProcessDpiAwareness(2)   # PER_MONITOR_AWARE_V2
```

不做的后果：`GetSystemMetrics` 返回逻辑尺寸（例如主屏 2560×1440 会变成 1707×960），
`SetWindowPos` 的坐标被系统按缩放再换算一次，窗口会跑到屏幕外或摆不正。
浏览器命令行 `--window-position` 同样受此影响，不可靠。

### 3. 判断“副屏黑”要看两种抓屏 API

| 抓屏方式 | 库 | 说明 |
| --- | --- | --- |
| GDI BitBlt | `mss` | 多显卡/叠加层场景常返回黑 |
| DXGI Desktop Duplication | `dxcam` | 更底层，仍可能拿不到硬件叠加层内容 |

`dxcam` 还要注意按 **GPU 索引**定位输出：

```python
dxcam.device_info()   # 哪块卡带哪个输出
dxcam.create(device_idx=1, output_idx=0)
```

两块屏挂在不同 GPU 上时，`device_idx=0, output_idx=1` 会 `IndexError`。

### 4. 鼠标锁：别自己写

自写 `ClipCursor` 若漏掉 DPI 感知，会把鼠标关进错误矩形，症状是**整个桌面点不动**，
且 `GetClipCursor` 看起来“正常”（返回的矩形在未裁剪时就是全屏）。
用成熟工具（CursorKeeper、Dual Monitor Tools）更安全。

### 5. 浏览器窗口的启动方式

```bat
msedge.exe --app=http://127.0.0.1:8080/remote ^
  --user-data-dir=<独立 profile> ^
  --no-first-run --no-default-browser-check --disable-sync --disable-session-crashed-bubble
```

`--app=` 去掉地址栏；`--disable-sync` 避免首次启动弹“同步浏览数据”对话框挡住画面。
窗口位置仍要用 API 摆（见第 2 点）。

## 排障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 副屏全黑，窗口有内容 | 远端软件硬件叠加层不支持非主输出 | 改用 `/remote` 浏览器显示 |
| 静止时不刷新 | 远端桌面本来就没变化 | 正常；对比两帧不同只说明有变化 |
| 抓到的图全黑 | 被抓窗口最小化 | 守护脚本还原它 |
| 副屏上有内容但点不动 | 有不可见顶层窗口在吞点击 | `WindowFromPoint` 定位后清掉 |
| 桌面整体点不动 | 残留 `ClipCursor`（DPI 算错） | 结束进程并 `ClipCursor(None)` |
