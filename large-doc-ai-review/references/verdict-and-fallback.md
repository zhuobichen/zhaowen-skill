# 结论分级与兜底

## 四档结论

源项目用这四档，覆盖了审核场景的几乎所有情况：

| 结论 | 含义 | 触发条件 |
|------|------|----------|
| `PASS` | 满足 | 有明确证据，且证据支持满足 |
| `FAIL` | 不满足 | 有明确证据，且证据支持不满足 |
| `SUPPLEMENT` | 需补材料 | 材料缺失但可以补齐（对应"补充材料"类要求） |
| `MANUAL_REVIEW` | 转人工 | 证据存在但无法可靠自动判定 |
| `NOT_EXIST` | 本项不涉及 | 该审查点对这份材料不适用 |

`NOT_EXIST` 很重要：一份材料不包含所有章节，如果把"没这一章"算成 FAIL，会产生大量假阳性。

## 必须转人工的清单

**这些绝不允许自动判定**，无论 OCR、LLM、定位器怎么说：

- 签字真伪
- 印章真伪
- 证照有效性
- 自动定位失败（"我没找到" 不等于 "它不存在"）

这是整个系统最重要的纪律。理由很直接：自动判"签字缺失"是漏判（材料其实签了，只是没识别出来），
自动判"签字存在"是误判（模型看到的是印刷体签字或扫描噪声）。两个方向都会让审核结论失去可信度。

所以规则是：

```text
涉及签字/印章/证照 -> 一律 MANUAL_REVIEW
除非有确定性的外部系统明确确认"不存在"
```

外部系统负责的审查项，返回**锁定的占位结果**，不要伪装成本地自动审查出来的。

## 整体结论聚合

优先级（从重到轻）：

```text
FAIL > SUPPLEMENT > MANUAL_REVIEW > PASS > NOT_EXIST
```

只要有一项 FAIL，整体就是 FAIL。`NOT_EXIST` 优先级最低因为它代表"不涉及"，不参与加权。

聚合时的完整性检查（缺一不可）：

- 配置里登记的每个审查点都必须有结果，不允许漏
- 不允许重复 `leafId`
- 不允许出现配置里没有的未知 `leafId`
- 每个结果必须带 `lockedScore=true` 和合法 score（由该审查点的执行器自己声明）

## 置信度

每个结论带一个 `confidence`。它的作用不是给人看分数，而是**决定要不要触发人工复核**。

实用做法：

```text
confidence < 阈值  -> 结论降级为 MANUAL_REVIEW，理由和证据照样保留
```

注意降级时**不要丢证据**。人工要看的就是这些页码和文本。

## LLM 三种失败都要兜底

| 失败模式 | 表现 | 兜底 |
|----------|------|------|
| 跳过 | 目录定位没找到对应材料 | 输出 `MANUAL_REVIEW` + 空 sourceInfo，标注"未定位到材料" |
| 报错 | 超时、429、500 | 有界重试后仍失败 -> `MANUAL_REVIEW` + 错误详情 |
| 非法输出 | JSON 解析失败、schema 不符、枚举值不在范围 | 尝试修复（截取最外层 JSON）-> 仍失败 -> `MANUAL_REVIEW` |

**兜底结果必须保留足够证据让人工复核**：页码、原文片段、失败原因、尝试次数。

一条实用原则：

```text
LLM 缺失/失败/非法 -> 明确的代码兜底 + 足够证据
```

不要静默吞掉异常返回空结果——人工看到"没问题"和"没检查出来"是两回事。

## 锁定分数

如果某个审查点有专属的 LLM 判断并返回了合法分数，聚合阶段应该**直接锁定这个分数**，不被通用打分器
覆盖。

```python
if dedicated_result and dedicated_result.score is not None:
    return {**dedicated_result, "lockedScore": True}
```

理由：通用打分器不知道这个审查点的特殊语义。让它覆盖专属判断等于白写。

## 该建专属审查模块的情况

- 某个审查点需要专门的 LLM prompt（大量材料特有规则）
- 某个审查点的分数来自确定性计算（预算加总、算术校验）
- 某个审查点由外部系统给结果

其余的走通用叶子打分器。别给每个审查点都建专属模块，那是过度设计。
