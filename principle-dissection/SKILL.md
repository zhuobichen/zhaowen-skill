# 拆解原理:把「做完了」变成「知道它里面都是什么」

> 一句话:**一个产物的「原理」,就是它底下用到的那些基本功。**
>
> 做完一个东西、却连它用的基本手段是什么都不知道,是尴尬,也是真空白。这份拆解的主体,就是**把那门基本功从零讲清**——不是教你「怎么挑它的错」。
>
> **顺序别搞反:先懂,后审。** 你连 SQLite 是什么都不知道时,「这个解析对不对」根本无从谈起。

---

## 动手前:先读「学习者基线」

**从零 ≠ 从绝对零。** 先读**学习者基线**（记录这个人已经会什么），讲的时候**跳过已会的、从他不懂的地方开始**。

- 本机基线：知识库仓库里的 `我的知识基线.md`（用户自己维护、可编辑）；换机器就问用户路径。
- 标「已会」的概念**直接当他会**，别浪费篇幅重讲；标「不会 / 未确认」的才从零讲。
- 讲完新学会的，**提醒用户回基线把那几行改成「已会」**——基线是活的。

---

## 第 0 步:先锁产物与它的「声称」

拆之前先答四句。答不出就问用户,别猜:

1. **它是什么?** 一句话,不含形容词。
2. **它声称能做什么?** ——这是坐标系。
3. **谁做的?** 自己写 / AI 生成 / 混合。**AI 生成成分越高,底下被你跳过的基本功越多。**
4. **我实际读懂了多少?** 给个诚实的百分比。

产物往往很大,别想着全拆。**只拆承重的那 20%**——"它一旦不成立整个东西就废"的部分。

---

## 第 1 步:拆出「它用到的每一门基本功」(核心之一)

**顺着数据流走,别顺着代码目录走:**

> 数据从哪来(文件?网络?别的进程?)→ 中间经过哪些转换 → 存到哪去 → 谁读它。

**每一处"你其实不懂它在干嘛"的地方,就是一门要讲的基本功。** 你不懂的黑箱,就是基本功清单的来源。

列成 5–10 门,**按承重排序**(错的代价最大的排前面)。

例(一个解析微信数据库的工具)会拆出:SQLite / 数据库 · 加密与密钥 · 读别的进程的内存 · 文件原子写与 Windows 文件语义 · CLI 的"两段式确认" · 进程间协议(如 MCP)……

---

## 第 2 步:每门「从零讲」(核心,主产出)

对每一门基本功,写四句话——**缺一句都不算讲完**:

1. **是什么**:一句话定义,**不假设你认识任何术语**;第一次出现的术语,先用大白话讲清。
2. **标准手段有哪些**:这个领域的人通常怎么做(2–4 种),各自适用什么场景。
3. **我这项目用的是哪一种**:落到**本产物的哪一块**(文件 / 函数 / 配置)。
4. **一个最小例子**:能上手的最小演示——一条命令、一段最小代码、或一张手画的关系。

**「从零」的硬标准:**

- 术语**不许不解释就用**。你写「SQLCipher 按页加密」之前,得先让人知道"页"是什么。
- 不假设读者懂行话(哪怕是"表/列/索引"这种)。
- 每个"**为什么这么做**"都要讲——只讲"怎么做"是说明书,不是原理。
- 配一个**最小可跑**的例子,而不是贴一大段项目代码。

> **失败模式**:写成「术语解释词典」或「通用知识介绍」——读者看完了,还是不知道**自己那个项目**里哪一块是它。
> **检查**:每一门都必须落到「我这项目用的就是它」。落不到,这门是凑数的。
>
> **检查(最关键)**:把这一门讲给一个**完全外行**,他能不能用自己的话复述"这是什么、为什么需要它"?不能 = 还没从零。

---

## 第 3 步(可选):想判它「靠不靠得住」时,再做「可靠边界」

**只在你(或用户)明确想"审它"时才做。不做也行——主体在上一节。**

沿用一小组动作(细节见 `references/`):

1. **信号地图**:我凭什么说它"对"?按 **廉价可验 / 昂贵可验 / 不可验** 分级,揪出最虚的一环。
2. **失效模式对照**:拿 `references/failure-modes.md` 逐项对照,标"适用且我现在没防"的。
3. **真跑一个 oracle 打脸**(不可跳):挑最虚的 1–2 点,从 `references/toolbox.md` 选一个能在本产物上真跑的手段(变异测试 / 属性测试 / 对拍 / 故障注入 / fuzz / 模型检查),跑出来,贴真实输出。**没跑 = 没做。**
4. **黑箱层**:哪些层是 AI 给的、你没读过的——给出"最少补哪一层"。

> 「能审而补的基础概念」见 `references/foundations.md`(那里也按"能不能让你判错"筛)。

---

## 第 4 步:复述 + 当考官挑漏洞

让用户用自己的话讲一遍。AI 当考官,**一次只问一个问题**,专问**第 2 步里讲得最虚的那门基本功**(而不是问他刚讲过、明显会的)。

```
我讲完了。请只根据我讲的内容,找出:哪句是推的、哪句是实测的、
哪句其实没讲清就滑过去了。一次只问一个问题。
```

产出:能讲清的 / 讲不清的(**讲不清的才是真没懂的**)。

> **失败模式**:AI 夸"你讲得很好"就通过。逼它**至少指出一处**"听起来高级但没说明白"的地方。

---

## 产出物:《原理拆解.md》(主体是知识)

用 `scripts/scaffold.py` 生成骨架,再逐段填。固定小节:

0. 产物与它的「声称」
1. **它用到的每一门基本功**(清单,按承重排)
2. **每门从零讲**(主体,占全篇一半以上)
3. 可靠边界(**可选**)
4. 复述与缺口

**输出位置**:用户指定;没指定就放 **D 盘**(本机偏好,别丢进 `C:\Users`)。
**两种读者两个形态**:机器/归档用 `.md`;给人读可另出一份**单文件、零 JS** 的 `.html`(证据/术语用徽章上色)。

## 贯穿原则

| 规矩 | 静默失败长什么样 | 怎么抓 |
|---|---|---|
| **主体是知识,不是验收** | 满篇"怎么验证",没讲清一个基本功 | 第 2 步占全篇一半以上? |
| **术语先定义再说** | 通篇行话,外行读不懂 | 讲给外行,他能复述吗? |
| **落到"我这项目用的哪一种"** | 读起来像通用百科 | 每门都能指到本产物的一块 |
| **别滑回验证** | 拆着拆着又开始写"怎么判错" | 验证只准出现在第 3 步 |

**两条硬规矩:**

1. 每一步都要有**可回看的产物**(最小例子、跑出的数、渲染的图),不能以"我懂了"结案。
2. **把「我推的」和「实测的」分开标**——几周后你会把"我推的"当成"实测的"引用自己。

---

## 什么时候不要用

- 用户要的是**学别人的东西** → `layered-explainer`
- 用户要**拆别人未公开的二进制/应用** → `reverse-engineer-anything`(REA)
- 用户要**系统性调研**某个主题 → `hv-analysis`
- 用户要学的是**一整门基础**(不挂具体产物) → 用 `layered-explainer` 方向 B
- 产物还在**造的过程中** → 先做完;边做边拆会两头空
- 用户**只想要结果**、不想理解 → 这是折磨,别硬上
- **你没法配最小例子** → 至少把"是什么 / 标准手段 / 本项目用哪种"三句写全,别只堆术语

## 文件

- `scripts/scaffold.py` — 生成《原理拆解.md》骨架(基本功为主体)
- `references/foundations.md` — 常见基本功领域的「判错概念 + 验收题」(第 3 步用)
- `references/toolbox.md` — 各语言/方向的验证工具(第 3 步选 oracle 用)
- `references/failure-modes.md` — 失效模式清单(第 3 步逐项对照用)
