# 微信公众平台的硬限制：做不到的事，与实测证据

本文件只记录一件事：**哪些需求在微信正文里根本做不到，以及为什么**。

目的是省掉重复试错——下面每一条都注明「实测」或「第三方资料」，别再试第二遍。

---

## 一、图片清晰度：1080px 是硬顶，原图无用

### 限制

| 项目 | 限制 |
|---|---|
| **正文图宽度** | **> 1080px 一律压到 1080px** |
| 单图大小 | ≤ 10MB（2023 年由 5MB 提升） |
| 单图像素 | 宽×高 ≤ 600 万 |

### 实测证据

- 上传 1440px 的图 → 微信存储 **1080px**
- 上传 1269px 的图 → 微信存储 **1080px**
- 把图片 URL 的尺寸参数换成 `/0`（通常表示原图）→ **返回的还是 1080px**，微信没有存更高清的版本

### 结论：**「上传原图」没有意义**

实操上唯一能做的是**自己先缩到 1080**（LANCZOS，高质量），避免微信再缩一次；
JPEG 给 `quality=95 + subsampling=0（4:4:4）`。这套已经做满，是公众号正文能达到的上限。

### 一个常见的误解

> 「提前缩到 1080、导出高品质，微信就不会二次压缩，画质损失最小」

**这句话是对的，但它解决的是「别再糊一层」，不是「糊」本身。**

大合照之所以糊，是因为 **8220px 的内容要塞进 1080px 的位置**——只剩 13%，
原图里 45px 的人脸压完只剩 6px。这是**降采样造成的信息量损失**，
把品质从 90 提到 95、提到 100 都改变不了：**丢的不是精度，是像素**。

> 实测：某会议全景合影 8220×3076 → 微信存储 1080×404，人脸约 6px，认不出人。

**唯一能改善的手段是「拆图」**——把宽图切成几条，每条吃满 1080 宽，
人脸能放大 3 倍（约 18px）。不拆就是天花板。

## 二、滚动条：既不能加粗，也不能常驻

用户诉求：把相册的横向滚动条**加粗 1.5 倍**、并**默认常显**（不要鼠标移过去才出现）。

**两条都做不到。** 三条路全部实测堵死：

### 路 1：`scrollbar-width` —— 没有数值可调

该属性只接受 `thin` / `auto` / `none`**三个关键字**，无法指定 1.5 倍。
而且实测**`thin` 反而最粗**：

| 设置 | 实际厚度 |
|---|---|
| `scrollbar-width:thin`（本 skill 在用） | **9px** |
| `scrollbar-width:auto`（默认） | 5px |
| 不写该属性 | 5px |

> 也就是说：**加粗这件事早就做到头了**，现在用的就是关键字里最粗的一档。

### 路 2：`::-webkit-scrollbar` —— 唯一能精确控宽/强制常驻的方法，但需要 `<style>`

实测三次，全部失败：

| 尝试 | 结果 |
|---|---|
| 正文里放 `<style>`（写 `color:rgb(255,0,0)` 验证） | ❌ **被剥**，颜色字号完全没生效 |
| `<svg>` 内部放 `<style>`（想借 SVG 自带的样式能力绕开） | ❌ **同样被剥**——`foreignObject` 残留了，但 `<style>` 没了 |
| 内联 `style` 属性 | ❌ 定义不了伪元素 |

**微信对 `<style>` 是无差别剥除，HTML 里剥、SVG 里也剥。**

> 参照：`::-webkit-scrollbar{height:14px}` 在能生效的环境下确实能做到 14px
> （约等于用户要的 1.5 倍），但这条路在公众号里是死的。

### 路 3：`overflow:scroll` / `scrollbar-gutter:stable` —— 只对经典型滚动条有效

只在**本来就是经典型**滚动条的系统上有意义；对浮层型无效。实测两者在本机都占 5px 空间（经典型）。

### 为什么「常驻」做不到（根本原因）

浏览器有两类滚动条：

| 类型 | 行为 | 谁能控制 |
|---|---|---|
| **经典型** | 常驻、占空间 | CSS（`overflow:scroll` 等） |
| **浮层型** | 平时隐藏，**滑动/悬停时才浮现** | **操作系统/浏览器设置，CSS 无权覆盖** |

触发浮层型的场景：**Windows 的「自动隐藏 Windows 中的滚动条」开关**、**macOS 默认**、
以及**所有移动端浏览器**（包括微信内置）。

**唯一能把元素强制切回经典型的手段就是 `::-webkit-scrollbar`**，而它被路 2 堵死。
所以「常驻滚动条」在公众号里做不到——**不是实现问题，是平台级限制，任何公众号都一样**。

### 可用的替代（不依赖滚动条）

- 相册下方常显的文字提示 `◁ 左右滑动查看更多 ▷`（2024 年那篇的官方做法，本 skill 已照抄）
- 相册右缘渐隐（未采用）
- 静态指示条轨道+滑块（做过，用户否决——会诱导用户去拖一个拖不动的东西）

## 三、动效：CSS 动画不行，GIF 可以

最初查 2024 模板时看到「正文 `animation`/`transition` 各 0 处」，**差点得出「动效做不了」的错误结论——漏了 GIF**。

### CSS 动画确实不行

1. `@keyframes` 只能写在 `<style>` 里 → 被剥（见上）→ 内联写 `animation:xxx` 也没用，动画名没定义
2. `transition` 需要 hover/active 触发，而内联样式定义不了伪类，移动端也没有 hover

### GIF 可行 ⭐

GIF 就是普通 `<img>`，微信正常上传播放，落在 `mmecoa_gif` / `mmbiz_gif` 上。

> 实解 2024 那篇文章，正文里有 **2 个 GIF 装饰件**（67 帧的小鸟、13 帧的下滑箭头），
> 页面上的 5 个 `@keyframes` 全在 `<head>` 里，是微信自己的 UI（`weuiAudioPlaying` 等）。

**管线接线要点**：GIF **绝不能走压缩流程**——会被重编码成 JPEG，只剩第一帧，动画全丢。
`compress_images` 里要对 `.gif` 原样跳过，`to_data_uri` 的 MIME 表要含 `image/gif`。

## 四、`<style>` 与 `class`：只有 `id` 能活

实测注入 `<style>` + `<p class="x" id="y">`：

| 元素 | 结果 |
|---|---|
| `<style>` | ❌ 被剥 |
| `class` 选择器 | ❌ 无效（样式没了，class 也没有意义） |
| **`id`** | ✅ **保留**（`getElementById` 能取到） |
| 内联 `style` 属性 | ✅ 保留 |

> 附带测试：用 `id` 做的**锚点跳转**（`<a href="#目标">`）在编辑器里**点击无效**
> （`scrollLeft` 不变）。发表后是否有效**未验证**（不能为了测试去发表）。

## 五、服务号 vs 订阅号：CDN 域名不同

| 账号类型 | 图片 CDN | URL 形态 |
|---|---|---|
| 订阅号 | `mmbiz.qpic.cn` | `mmbiz_gif` / `mmbiz_jpg` |
| **服务号** | **`mmecoa.qpic.cn`** | `mmecoa_gif` / `mmecoa_jpg`（也见 `sz_mmecoa_jpg`） |

**踩过**：把「src 含 `mmbiz.qpic.cn`」当作「上传成功」的判据，推到服务号上会**全部误报失败**
（实测 50 张图全传成功，校验却报 `CDN 数 0 ≠ 总数 50`）。判据改成「含 `qpic.cn`」即可。

**封面比例也不同**：

| | 裁剪框 |
|---|---|
| 订阅号 | `2.35:1（消息列表）` + `1:1（转发卡片和公众号主页）` |
| **服务号** | `1:1（服务号列表）` + `2.35:1（服务号会话）` |

## 六、封面的两个坑

**坑 1：索引 0 可能是装饰 GIF，选了会得到一张纯黑封面。**

正文里插了 GIF 装饰件后，**封面选择器会把 GIF 也列进去**（我们的装饰 GIF 排在开篇卡片之前，
所以恰好是索引 0）。**微信的裁剪工具处理 GIF 会产出纯黑图**——封面设了、URL 也有、
尺寸也对（466×198），但内容是纯黑。

> 实测：`fetch` 下封面字节量像素，平均 RGB `[0,0,0]`；纯黑 JPEG 压出来才 0KB。

**正确做法**：按**显示宽度**挑（装饰 GIF 是 46px，正文图是 578px），不要盲选索引 0。

**坑 2：选完要等裁剪预览渲染完再点「确认」**，大图慢，抢时间可能在空 canvas 上裁出黑图。

> **检查封面不能只看「有没有 background-image」**——我第一次就是这样误报「封面正常」，
> 白白让用户自己发现是黑图。要**把图拉下来量像素**才算验过。
